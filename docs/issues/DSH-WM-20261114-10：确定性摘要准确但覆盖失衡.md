# DSH-WM-20261114-10：确定性摘要准确但覆盖失衡

## 问题信息

- 发现日期：2026-11-14
- 发现方式：用户评估摘要是否应由模型整理，以及是否只在 DSH 启动时更新
- 复现工作区：测试工作区
- 相关模块或代码：`src/core.ts` 的 `deterministicSummary()` 与 `rebuildSummary()`、`src/index.ts` 的系统提示摘要注入
- 状态：待方案确认
- 验证情况：已确认条目变更会将已成功生成的模型语义摘要覆盖为确定性拼接摘要，并受 24 小时模型冷却限制；原实现虽通过自动化检查，但不满足摘要质量与展示连续性要求

## 问题描述

当前 `memory_summary.md` 不是语义摘要，而是将有效结构化条目按 importance 和更新时间排序后，依次拼接 `title: description`，达到 3,000 bytes 即停止。该方式不调用模型、不会新增或改写事实，因此事实准确性较高，但不能合并重复、理解主题关系、平衡不同类别或提炼工作区主线。

测试工作区当前有 37 条 active 记忆，摘要为 2,883 bytes，只容纳 5 条，且全部属于 TTS 定价或模型选型主题。姓名、年龄、现居城市等用户画像和其他项目事实没有进入摘要，说明当前摘要覆盖失衡，不能等同于高质量的工作区总览。

后续真实使用进一步确认：模型成功生成带章节和语义归纳的摘要后，只要同一 scope 的结构化条目发生新增、更新或删除，`rebuildSummary()` 就会立即用确定性条目拼接覆盖同一个 `memory_summary.md`。由于后台模型摘要仍按上一次尝试时间执行 24 小时冷却，高质量语义摘要可能在一次普通记忆变更后消失近 24 小时。两种摘要不是同时注入造成内容冲突，而是在同一文件上前后覆盖；从用户看到和 Agent 实际获得的结果看，构成了摘要策略冲突。

2026-11-14 真实全局记忆证据：21:48 的模型调用成功，22:22 的历史版本仍为带“用户画像”“规则与偏好”等章节的语义摘要；22:32 和 22:34 的条目变更又将其覆盖为 `title: description [tags]` 列表。当前 `summary_meta.json` 为 `mode: deterministic`，同时保留早先的 `semanticLastSuccessAt`，证明模型摘要成功后确实被后续确定性重建替换。

## 影响

- 前台 Agent 每个 step 都会收到稳定摘要，但摘要可能被少数长条目和近期单一主题占满。
- 摘要虽然不容易幻觉，却可能遗漏对当前会话更重要的长期事实。
- 单纯增加摘要字节上限会增加每个前台模型调用的上下文成本，不能解决主题失衡。
- 只在 DSH 启动时更新摘要会使长时间运行的服务持续使用陈旧摘要；频繁重启又可能产生不可控的重复模型调用。
- 用户无法稳定获得模型已经生成的分章节语义摘要；设置页看到的摘要质量会随条目变更在语义版与拼接版之间来回降级。
- 24 小时冷却本应限制昂贵的完整重算，却同时阻止了被覆盖后的语义摘要及时恢复。

## 原因判断

确定性摘要承担了两个目标：作为结构化记忆的可靠投影，以及作为面向模型的语义压缩。前者适合本地规则，后者需要主题平衡和语义综合；由同一个简单拼接实现同时承担，导致接口很小但行为深度不足。

原双层方案又让两种产物共用同一个展示和注入文件：条目变化时以正确性为由覆盖语义摘要，再由低频模型任务恢复。这使“安全回退”变成了正常主路径，并把 24 小时冷却错误地应用到条目变化后的恢复过程。

## 解决方案

1. 结构化记忆条目继续作为唯一事实来源，模型摘要只能是可重建的派生数据，不能反向修改条目。
2. 用户可见并注入前台的主摘要只使用模型生成的语义摘要。确定性条目拼接不得再覆盖 `memory_summary.md`，最多保留为不展示、不注入的内部诊断或灾难恢复数据。
3. 条目新增后保留上一版语义摘要，并临时补充有界的新增 active 条目；经过短防抖后由模型更新受影响的语义章节。
4. 条目被修订、取代或删除时，旧语义摘要可能包含失效事实，不能继续作为可信摘要注入。应立即将对应语义摘要标记为不可注入，短防抖后优先调用模型重建；完成前由权威 active 条目的相关记忆检索保证可用性，而不是显示原始条目拼接摘要。
5. 将 24 小时限制用于无变化时的周期性完整校准，不用于阻止条目变化后的增量语义更新。启动时只恢复 dirty 任务，不因每次启动无条件调用模型。
6. 为控制 Token，不在每次变化后把全部历史条目重新发送给模型。推荐按用户画像、项目事实、决策、规则、修复等类型保存模型生成的语义章节，只重算发生变化的章节，再由程序组合这些模型章节；组合行为不能把原始条目机械拼接进主摘要。
7. 新结构化条目仍可立即通过相关记忆检索用于新 Session，因此语义摘要允许短暂延迟更新，不阻塞记忆连续性。
8. 模型只输出 Markdown 摘要正文，不负责机械抄写来源 ID。程序记录本次实际送入模型的 entry ID，并在提交前校验这些来源仍为 active；校验失败时保持 dirty 并重试，不将确定性拼接发布成主摘要。
9. 另行评估稳定摘要是否需要注入每个 Agent step；可以只在每个用户 turn 的第一步注入，后续工具 step 依靠同一上下文或缓存，降低前台模型 Token。

## 处理记录

- 2026-11-14：确认当前摘要为本地确定性拼接，不进入记忆整理模型请求，也不产生记忆整理 Token。
- 2026-11-14：真实工作区检查显示 37 条 active 记忆仅有 5 条进入 2,883-byte 摘要，且 5 条全部属于 TTS 主题。
- 2026-11-14：将“即时可靠投影”和“低频语义压缩”拆为两个模块，避免用每日或启动定时器同时承担正确性与摘要质量。
- 2026-11-14：新增 `summary_meta.json`，记录 active 条目来源指纹、确定性/语义模式、模型摘要尝试与成功时间及来源 ID。
- 2026-11-14：条目变化立即回退到确定性摘要；语义摘要默认等待 60 秒、每 scope 最多 24 小时一次，并与实时整理共享模型并发额度。
- 2026-11-14：语义摘要输入按记忆类型轮询，限制为 24 KB；程序只记录本次有界输入的来源 ID，提交时再次校验全部 active 条目来源指纹。
- 2026-11-14：DSH 启动校验摘要文件与来源指纹，缺失或陈旧时先本地修复，再恢复到期的后台语义摘要任务。
- 2026-11-14：真实模型首次要求输出摘要和完整 `sourceIds` 时，两个较大工作区均发生格式或来源校验失败；确定性摘要安全回退有效，但产生了无效调用成本。
- 2026-11-14：将模型契约收窄为约 450 汉字的纯 Markdown。来源 ID 改由程序从 24 KB 有界输入记录，保留 active 指纹和提交前校验；新增不依赖模型 JSON 或复制来源 ID 的运行时回归测试。
- 2026-11-14：后台摘要定时器使 Windows 测试清理出现写入竞态，测试清理改为先释放 Cordis fiber、取消定时器，再删除临时目录；完整测试连续两次通过。
- 2026-11-14：当前 `3080` DSH 通过本地 Junction 加载新构建。37 条测试工作区和 24 条工作区均成功切换为 semantic，条目数量未变化。
- 2026-11-14：用户真实使用发现后续记忆变更再次把带章节的语义摘要覆盖为确定性拼接摘要。核对全局 `summary_meta.json` 和 `summary_history/` 后确认覆盖链条，原双层方案不能视为已完成。
- 2026-11-14：方案调整为“模型语义摘要是唯一发布摘要；确定性机制只做内部校验/恢复，不覆盖展示与注入；条目变化触发按章节的短防抖增量语义更新；24 小时仅用于周期性完整校准”，等待用户确认后实施。

- `pnpm typecheck`：通过。

- `git diff --check`：通过。

以上验证只能证明原实现按其设计运行，不能证明产品行为正确。后续方案实施后需新增“模型语义摘要生成后发生新增、修订和删除，主摘要不得退回原始条目拼接”的自动化回归测试，并在当前 `3080` DSH 上验证语义章节连续性与旧事实失效行为。
