# DSH-WM-20261116-02：删除记忆后的摘要更新状态不可见

## 问题信息

- 发现日期：2026-11-16
- 发现方式：用户删除结构化记忆后观察到摘要短暂变化，询问防抖期间的页面状态和检索可用性
- 相关模块或代码：`src/index.ts` 的语义摘要调度与 Browser API、`src/client/index.tsx` 的摘要区
- 状态：已解决
- 验证情况：删除响应、scope 状态、摘要区提示和完整构建均已通过自动化验证

## 问题描述

结构化记忆新增、编辑或删除后，受影响的语义摘要主题会立即失效，并在默认 60 秒安静期后由模型增量重建。现有设置页只显示当前仍有效的摘要或“暂无摘要”，没有说明摘要已进入更新队列、预计何时开始，也没有列出受影响主题。用户因此可能把正常的防抖等待误认为摘要丢失或删除范围异常。

## 影响

- 用户无法判断摘要为空是从未生成，还是因条目变化正在安全重建。
- 连续删除多条记忆时，无法看到 60 秒防抖已被重新计时。
- 摘要恢复后页面会通过现有轮询自动刷新，但等待期间缺少可解释状态。
- 结构化记忆检索仍以权威条目为准，不受摘要重建影响；当前页面没有把这一点表达清楚。

## 原因判断

语义摘要定时器及运行状态只保存在运行时内部，Browser API 没有输出摘要刷新状态；删除接口只返回 `scope` 与 `deleted`。客户端因此无法区分普通空摘要与失效后等待重建的摘要。

## 解决方案

1. 运行时记录每个 scope 的摘要任务预计开始时间和执行阶段。
2. 根据当前 dirty topics 输出受影响主题，避免把不受影响的摘要章节标为更新中。
3. 删除接口立即返回摘要刷新状态；scope API 在后续轮询中返回同一状态。
4. 摘要区保留仍有效的主题内容，同时显示“摘要正在更新”、受影响主题、预计开始时间，并说明模型生成通常还需几十秒。
5. 连续变更继续复用现有 trailing-edge 60 秒防抖：每次新变更重置计时，只在最后一次变更安静 60 秒后发起模型调用。

## 处理记录

- 2026-11-16：确认现有 60 秒机制属于尾沿防抖，不是逐条任务队列；连续删除会合并为一次增量摘要调用。
- 2026-11-16：确认设置页已有 5 秒轮询，可用于更新倒计时状态并在摘要生成后自动恢复，不需要新增实时连接。
- 2026-11-16：新增失败优先回归断言，覆盖删除响应、scope 查询和中英文界面提示。
- 2026-11-16：运行时为每个 scope 记录摘要定时任务的预计开始时间与实际运行时间；Browser API 根据当前来源动态计算 dirty topics，只在确有失效主题时返回更新状态。
- 2026-11-16：DELETE 响应立即返回 `summaryRefresh`，scope API 在现有 5 秒轮询中持续返回同一状态；更新完成后状态自动回到 `idle`。
- 2026-11-16：摘要区新增状态提示，显示预计开始倒计时、模型通常所需时间和受影响主题，同时明确结构化记忆仍可检索。仍然有效的摘要主题继续展示，不清空整个摘要区。
