# DSH-WM-20261114-09：记忆整理候选检索过宽导致短对话高 Token 消耗

## 问题信息

- 发现日期：2026-11-14
- 发现会话：`session-9827c89e-467c-4977-a4a8-92f1806e3ea9`
- 复现工作区：测试工作区
- 相关模块或代码：`src/core.ts` 的 `selectDistillationCandidates()`、`src/index.ts` 的 `runDistillationCall()`
- 状态：已解决
- 验证情况：自动化检查通过；已在当前 DSH 持久化数据上重放原始两轮 checkpoint，候选分别降为 0 bytes 和 291 bytes

## 问题描述

运行时注入消息过滤修复后，两轮很短的真实对话仍使记忆整理累计量从 13,364 Token 增长到 20,971 Token。真实对话正文很短，但当前候选选择会使用用户和助手的完整文本检索旧记忆，并无条件补入最近 8 条可召回记忆，最终给每次整理请求携带大量不相关旧记忆。

这种行为不会随着全部记忆无限增长，因为已有 20 条和 12 KB 上限，但每轮都可能接近该上限。对于只有一句新事实的小对话，这个固定成本明显偏高。

## 证据与复现

两轮调用的累计增量为：

```text
calls          +2
inputTokens    +7,414
cacheReadTokens   +51
outputTokens     +142
totalTokens    +7,607
failures          0
reasoningTokens   0
```

对应 checkpoint：

```text
2026-11-14 21:18:08  Conversation 357 字符，模型无记忆操作
2026-11-14 21:19:21  Conversation 199 字符，新增“用户现居上海市”事实
```

按调用时点的记忆集合重放当前 `selectDistillationCandidates()`：

```text
第一轮：41 条可用记忆中选入 19 条，existing_memories JSON 9,832 bytes
第二轮：约 42 条可用记忆中选入 17 条，existing_memories JSON 约 9,387 bytes
```

候选中包含与居住地无关的 TXT 文件、modsearch、Qwen TTS、HeyGen、OpenRouter 等记忆。运行时注入内容已不在 checkpoint 中，因此本问题不是上一问题的过滤回退。

缓存也没有抵消主要成本：两次调用只新增 51 个缓存读取 Token，7,414 个输入 Token 基本都是未缓存输入。

## 影响

- 短对话也会产生约 3,000～4,000 Token 的单次整理输入。
- 无关旧记忆不仅增加成本，也可能干扰模型判断新增、修订和冲突关系。
- 工作区记忆越丰富，单次请求越容易接近 12 KB 候选上限。
- 当前整理模型几乎没有复用这两次调用的重复前缀，不能依赖缓存解决问题。

## 原因判断

1. 候选检索使用用户与助手完整正文。助手回复会重复工作区画像和背景资料，扩大检索词集合。
2. `selectDistillationCandidates()` 在词法命中和同主题候选之后，无条件加入最近 8 条记忆；即使没有相关命中也会发送旧记忆。
3. 默认上限为 20 条/12 KB，更偏向召回完整性，没有针对每轮实时整理的成本做约束。
4. 模型请求中的固定规则提示会产生基础开销，但本次主要可削减部分是每轮约 9～10 KB 的 `existing_memories`。
5. `memory_summary.md` 不会进入记忆整理模型请求。当前摘要由结构化条目在本地确定性生成，不调用 LLM；它与 `existing_memories` 是两条独立路径。

## 解决方案

1. 候选检索查询只使用用户消息；助手正文仍作为待提取对话提供给模型，但不参与旧记忆召回。
2. 移除无条件的最近记忆补位。没有相关词法或主题命中时，发送空的 `existing_memories`。
3. 将实时整理候选限制收紧到约 4～6 条、最多 3 KB；相关候选优先，不为凑满数量加入无关项。旧条目不能完全取消，因为 revise、supersede、冲突判断和去重仍需要少量真正相关的目标条目。
4. 增加候选相关性回归：居住地对话不能带入 TTS、文件和搜索工具记忆；已有同一居住地记忆时仍必须能够召回并执行 revise 或冲突判断。
5. 在 checkpoint 或诊断日志中记录单次调用的候选数量、候选字节数及 TokenUsage，便于后续定位成本回退，但不增加普通设置页信息密度。
6. 摘要继续在结构化条目真正新增、修订、取代或删除时本地即时重建，保证下一次对话立即看到新事实；DSH 启动时增加摘要缺失或陈旧校验作为补漏。
7. 移除“每 5 个成功 checkpoint 即使条目未变化也重建摘要”的兜底，避免无意义文件和历史版本写入。该调整只减少本地 I/O，不影响记忆整理 Token。
