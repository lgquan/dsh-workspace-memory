# DSH-WM-20261114-01：记忆设置页未同步工作区显示名称

## 问题信息

- 发现日期：2026-11-14
- 发现会话：Codex 会话 `01a1d968-d8ce-7a33-b881-8e10529087ef`
- 相关模块或代码：`src/client/index.tsx`、`src/index.ts`、`@deepseek-ai/dsh-workspace`
- 状态：已解决
- 验证情况：已完成 Host 标题接入、轮询同步和同名消歧；自动化测试、构建和 DSH `0.2.2-rc.1` 隔离 profile 加载验证通过

## 问题描述

记忆设置页的工作区选择器显示目录最后一级名称，而不是 DeepSeek Harness 工作区注册表中的用户可见名称。用户在宿主中重命名工作区后，记忆页仍显示旧的目录名称；多个工作区目录同名时无法可靠区分。

## 证据与复现

- `src/client/index.tsx` 的 `workspaceName()` 仅从 `cwd` 截取最后一级目录。
- `/workspace-memory/api/v1/scopes` 当前只返回 scope 的 `key`、`cwd`、统计信息等，不返回工作区显示名称。
- 插件已经依赖 `WorkspaceRegistry`，但只用 `registry.list()` 的 `path` 判断 scope 是否仍属于已注册工作区，没有使用同一记录的 `title`。
- DSH 的 `Workspace` 正式契约包含持久化 `title`、`updatedAt` 和 `setTitle()`；工作区重命名后，宿主注册表是显示名称的权威来源。

复现步骤：

1. 注册两个末级目录同名、路径不同的工作区。
2. 在 DSH 中将两个工作区改成可区分的显示名称。
3. 打开设置页的“记忆”页面。
4. 工作区选择器仍显示相同的末级目录名，宿主显示名称没有同步。

## 影响

- 用户可能查看或判断错误项目的记忆。
- 工作区重命名无法反映到记忆管理界面。
- 同名目录下拉项无法仅凭当前标签区分，增加误操作风险。

## 原因判断

已确认根因是记忆页自行从路径推导名称，没有读取或订阅宿主工作区的 `title`。这不是显示缓存未刷新，而是数据源选择错误。

## 解决方案

1. 活跃 scope 的显示名称以 DSH 工作区注册表的 `title` 为权威来源，按规范化 `path/cwd` 关联，scope 身份仍保持现有基于 `cwd` 的稳定哈希，不因重命名改变。
2. Browser API 每次读取 scope 列表时从 DSH `WorkspaceRegistry` 取得最新 `title`；客户端每 5 秒轮询，使工作区重命名在已打开的记忆页中同步反映。无法取得宿主记录时回退到目录末级名称。
3. 选择器保留路径信息用于消歧。显示名称重复时至少追加父路径或完整路径；当前选中项继续展示完整 `cwd`。
4. 回收区中的已删除工作区没有持续存在的宿主记录，暂时使用已保存名称或路径回退，不能把已失效注册表当作权威来源。
5. 增加测试覆盖：宿主标题优先、标题变更同步、同名标题/同名目录消歧、无宿主记录时回退，以及重命名不改变 memory scope key。

## 处理记录

- 2026-11-14：核对当前客户端和 Browser API，确认选择器标签完全由 `cwd` 最后一级目录生成。
- 2026-11-14：核对 DSH Workspace 契约，确认 `Workspace.title` 是持久化用户可见名称，且重命名会更新同一工作区实体，不需要插件维护另一份活跃名称。
- 2026-11-14：用户确认方案，开始实施 DSH 工作区标题接入、标题变更同步和同名消歧。
- 2026-11-14：`/workspace-memory/api/v1/scopes` 按规范化路径关联 Host 工作区并返回 `workspaceId/title`；记忆 scope key 继续只由 `cwd` 决定。
- 2026-11-14：客户端优先显示 Host `title`，显示名称重复时追加完整 `cwd`，并每 5 秒更新 scope 列表和当前后台状态。
