# DSH-WM-20261114-02：记忆整理模型缺少可视化固定选择

## 问题信息

- 发现日期：2026-11-14
- 发现会话：Codex 会话 `01a1d968-d8ce-7a33-b881-8e10529087ef`
- 相关模块或代码：`src/index.ts`、`src/client/index.tsx`、`cordis.patch.yml`、DSH model catalog/settings API
- 状态：已解决
- 验证情况：已完成模型目录、固定路由、Settings 热更新和不可用状态；自动化测试、隔离 profile 以及当前 DSH `web` profile 的真实读写验证通过

## 问题描述

插件支持通过静态配置指定 `summarizeProvider` 和 `summarizeModel`，但记忆设置页没有模型选择或当前路由状态。普通用户无法从 DSH 已配置模型中固定一个专用于记忆整理的模型，也无法看出后续整理将使用哪个模型。

## 证据与复现

- `src/index.ts` 已声明 `summarizeProvider` 和 `summarizeModel` 配置字段。
- `distill()` 仅在两个字段都非空时使用固定路由；否则每次整理时调用 `agentDefaultModel.currentSelection()`。
- 因此当前默认行为不是继承某个工作区或某个会话的会话级模型，而是跟随 DSH 的全局默认 Agent 模型。全局默认模型后续变化时，新的记忆整理也会随之变化。
- `cordis.patch.yml` 没有配置这两个字段，当前安装默认走全局默认模型。
- 当前记忆设置页只提供 scope 浏览、搜索和回收区，没有模型目录、选择、保存或路由失效提示。
- 当前 DSH `0.2.2-rc.1` 已公开 `session.modelCatalog()`，返回当前可路由 provider/model 分组、默认选择和局部失败，能够作为模型选择器的权威数据源。
- 2026-11-14 在当前 `web` profile 稳定复现模型切换失败：`PUT /workspace-memory/api/v1/settings` 返回 `400`，错误为 `No configurable plugin entry "include:workspace-memory"`；模型目录校验此前已经通过，因此失败点位于 Settings 写入。

## 影响

- 记忆整理成本、速度和输出稳定性会随全局默认模型变化。
- 用户无法为后台记忆任务选择更适合的固定模型。
- 插件虽有固定路由能力，但只能手工修改配置，功能不可发现且容易配置错误。
- 固定模型被移除或失效时，当前界面无法解释 pending 持续重试的原因。

## 原因判断

运行时路由能力已经存在，缺口集中在客户端模型目录接入、持久化写入、配置即时生效以及失效状态呈现。直接复用会话级 `ModelSelect` 不合适，因为它的选择动作会修改具体 Session；记忆整理需要独立于 Session 的插件级配置。

当前本机 DSH 已是 `0.2.2-rc.1`，而仓库和已发布插件 `0.2.16` 仍面向 `0.2.1-rc.2`。继续开发前需要先完成并验证 DSH `0.2.2` 兼容迁移，避免基于旧契约新增界面和配置写入。

模型切换回退的直接原因是把 Loader 内部条目 ID `entry.id`（Include 场景为 `include:workspace-memory`）传给 `SettingsForms.update()`。Settings 的公开命名空间来自 `entry.options.id`（此处为 `workspace-memory`），`describe()` 和配置编辑器写入均使用这个公开值，因此内部 ID 无法匹配可配置条目。

## 解决方案

1. 在记忆设置页增加一个“记忆整理模型”选择器，数据来自 DSH `LlmRuntime` 的 provider/model 目录，只列出当前可路由且已广告的模型，按 provider 分组显示。
2. 不提供“跟随 DSH 默认模型”；初始固定路由为 DSH 账户的 `deepseek-account + deepseek-flash`，用户选择其他具体模型后保存完整的 `provider + model`。
3. 将 `summarizeProvider`、`summarizeModel` 改为可热更新配置，通过 DSH 官方 settings/config editor 路径持久化，保存后无需重启即可用于下一次整理。
4. 已保存模型暂时不在 catalog 时保留原选择并显示“当前不可用”，不静默切换其他模型；pending 消息继续保留，用户可以选择新的可用模型。
5. 记忆整理不复用或修改任何具体 Session 的模型选择，工作区会话切换模型也不应影响已固定的整理模型。
6. 增加测试覆盖：默认 DSH 账户模型、固定模型路由、保存后即时生效、配置跨重启持久化、不可用模型提示和无声回退禁止。
7. 实施前先升级并验证 DSH `0.2.2-rc.1` 依赖矩阵、Cordis `4.1` 和客户端 Remote/Workspace 契约。
8. 保存固定模型时使用 Loader 条目的公开 profile 命名空间 `entry.options.id`，不使用可能带 Include 前缀的内部 `entry.id`。
