## 问题描述

用户在测试工作区明确表示“我住在青浦区”。居住地属于跨项目有效的稳定用户画像，预期应修订 global 中已有的“用户现居上海”条目；实际却在测试工作区新增了一条 workspace 记忆，global 条目仍停留在“现居上海市，未提供具体区”。

结果是同一用户事实同时存在于两个 scope，且内容精度不同：其他工作区只能看到旧 global 事实，测试工作区则同时看到旧 global 摘要和新 workspace 事实。

## 证据与复现

原始 session v4 事件显示：

```text
seq 45 user: 我住在青浦区
seq 46 assistant tool-call: memory_remember
arguments: content=用户现居上海市青浦区；tags=用户信息,居住地；importance=2
seq 48 tool result: Memory stored in ws-6378a15eed293316ee90 (added=1, updated=0)
```

调用参数没有 `scope` 或已有 global 记忆 ID。调用发生前，模型上下文已经包含 global 语义摘要，其中明确存在“居住地：现居上海市，未提供具体区”。因此不是模型没有看到旧事实，而是显式工具没有提供修订该 global 条目的接口。

持久化结果：

```text
global/memory_entries.json
  mem-739756c33f30: 用户现居上海市；未提供具体区

scopes/ws-6378a15eed293316ee90/memory_entries.json
  mem-e28e2820ff64: 用户现居上海市青浦区
```

22:07:17 的后台 checkpoint 对该轮输出 `(none)`，说明错误条目来自前台显式工具调用，后台整理器没有新增、修订或迁移操作。

可重复只读检查结果：

```text
FAIL: global has old residence=mem-739756c33f30;
Qingpu persisted only in workspace=mem-e28e2820ff64
```

## 影响

- 姓名、年龄、居住地等用户画像可能在不同工作区各自形成副本。
- 其他工作区继续使用陈旧 global 画像，跨项目记忆失去一致性。
- 当前工作区会同时召回 global 旧事实和 workspace 新事实，可能导致冲突回答。
- 设置页手工修复只能逐条编辑或删除，不能从根源阻止后续再次错分。

## 原因判断

1. `memory_remember` 的描述明确限定为 current workspace，参数只有 `content`、`tags` 和 `importance`，没有 `scope`。
2. `memory_remember` 执行时未传 `scope`；`remember()` 因而按默认分支写入当前 `cwd` 对应的 workspace。
3. 已注册的 Agent 工具没有 `memory_update`；即使模型从摘要知道 global 中已有旧事实，也拿不到条目 ID，不能跨 scope 修订。
4. 后台整理提示只将“用户长期偏好和通用工作方式”明确归为 global，没有完整定义姓名、年龄、居住地等稳定用户画像的作用域规则；显式工具与后台整理也没有共享一套分类策略。

## 解决方案

1. 定义统一作用域规则：稳定用户身份与画像、跨项目偏好和通用工作方式属于 global；仅对当前项目成立的事实、决策、架构、规则和修复属于 workspace。
2. 为 `memory_remember` 增加必填的 `scope: global | workspace`，在工具参数说明中给出用户画像和项目事实示例，避免静默默认到 workspace。
3. 注册可供 Agent 使用的 `memory_update`，参数包含 `id`、`scope` 和结构化字段；global 条目只能在明确传入 global 时更新。
4. 让 `memory_search` 的结果明确返回每条记忆的 `id` 和 `scope`，并在工具说明中要求：已存在同一事实时先搜索再更新，不新增跨 scope 副本。
5. 后台整理和显式工具共用同一份 scope 分类规则，补齐“姓名、年龄、生日、居住地等稳定用户画像属于 global”的提示与回归测试。
6. 增加端到端回归：已有 global“现居上海”时，用户在任意工作区说“我住在青浦区”，最终只能修订 global 条目，workspace 不得新增副本。
7. 实施后迁移本次错误数据：将 global `mem-739756c33f30` 修订为青浦区，并软删除 workspace `mem-e28e2820ff64`；迁移前保留 revision 和来源审计。
