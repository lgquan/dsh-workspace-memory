# DSH-WM-20261114-05：记忆整理默认启用模型推理增加延迟与成本

## 问题信息

- 发现日期：2026-11-14
- 发现会话：Codex 会话 `01a1d968-d8ce-7a33-b881-8e10529087ef`
- 相关模块或代码：`src/index.ts`、DSH `LlmRuntime.prepareCall()`、模型 reasoning metadata
- 状态：已解决
- 验证情况：已通过 `prepareCall()` 实施自动最小推理；`off`、最低非 `off`、无 reasoning metadata 三类自动化用例及当前 DSH 实例加载验证通过

## 问题描述

记忆整理是一个后台结构化提取任务，当前插件固定 provider/model，但调用 `llm.stream()` 时没有指定 `reasoningEffort`。这不会继承或修改具体聊天 Session 的思考开关，却会采用所选模型路由的适配器默认推理档位。

当前默认整理路由 `deepseek-account/deepseek-flash` 使用 DSH DeepSeek Messages 适配器。该适配器在没有显式 request 值、provider 覆盖或全局禁用时将推理档位解析为 `high`，因此目前的记忆整理实际会启用高档推理。

## 证据与复现

- `src/index.ts` 的整理请求只传入 `provider`、`model`、`messages`、`system` 和 `maxTokens`，没有传入 `reasoningEffort`。
- DSH `GenerateOptions` 提供统一的 `reasoningEffort`，`LlmResolvedModelInfo.reasoning` 会声明该模型支持的档位及适配器默认档位。
- DSH 会在 provider I/O 前校验显式档位；模型不支持时返回 `UNSUPPORTED_REASONING_EFFORT`，不会静默转换为其他档位。
- DeepSeek 适配器对 `off` 统一映射为 `thinking: { type: "disabled" }`，其他档位映射为启用 thinking 及对应 effort。
- DeepSeek 适配器未配置 `thinking` 或 `reasoningEffort` 时，exact-model metadata 的默认档位为 `high`。
- DSH 核心模型调用 API 是流式协议。插件只收集 `text-delta`，完整结束后才解析 JSON，不向聊天界面输出增量；流式传输与是否启用推理是两个独立维度。

## 影响

- 高档推理会增加记忆整理的首字延迟、总耗时和推理 token，降低后台队列吞吐量。
- 频繁近实时整理时，额外成本会随调用次数放大。
- 当前设置页只固定 provider/model，用户无法从界面看出实际采用了适配器默认高推理。
- 直接修改 provider 的全局 thinking 配置会同时影响聊天等其他调用方，不符合记忆整理与前台会话隔离的目标。

## 原因判断

固定模型只隔离了 provider/model 路由，没有为后台任务选择独立的 per-call 推理控制。调用方省略 `reasoningEffort` 后，DSH 按 exact-model adapter metadata materialize 默认值；对当前 DeepSeek 路由而言就是 `high`。

记忆整理仍需要分类、去重、纠错和冲突判断，但现有结构化提示已经限定了输出和证据规则。对 Flash 类模型而言，默认高推理相对任务复杂度偏重；优先关闭或降至最低档更符合延迟与成本目标，准确率风险应由回归样例和真实记忆质量观察验证。

## 解决方案

1. 不在设置页增加独立“思考开关”，避免暴露不同 provider 的实现差异；模型选择仍只保存 provider/model。
2. 每次整理通过 `LlmRuntime.prepareCall()` 原子获取 exact-model metadata 并绑定实际 dispatch，防止模型配置热更新期间能力判断与请求路由不一致。
3. 自动选择最小推理策略：模型声明支持 `off` 时显式使用 `off`；模型不声明 reasoning 能力时不传该字段；模型支持 reasoning 但没有 `off` 时使用其广告列表中的最低档。
4. 继续使用 DSH 的流式传输协议，但仅在后台收集最终文本并解析 JSON，不向用户界面流式展示，也不保存 reasoning 内容。
5. 不读取、修改或保存 `agentDefaultModel` / Session 的 reasoning selection，保证工作区聊天的模型与思考配置不受影响。
6. 增加测试覆盖：支持 `off`、无 reasoning 能力和只有非 `off` 档位，确认最终发给适配器的请求参数符合模型 metadata。

## 后续低优先级优化
