# DSH-WM-20260830-02：设置页主题颜色在明暗模式下不可读

## 问题信息
- 发现日期：2026-08-30
- 发现会话或复现方式：用户提供深色和浅色设置页截图
- 相关模块或代码：`src/client/index.tsx` 的记忆设置页
- 状态：已解决
- 验证情况：`pnpm check`、`pnpm build`、`git diff --check` 均通过

## 问题描述

记忆设置页使用了宿主不存在的 `--ds-color-*` 主题变量。变量回退值固定为浅色文本和半透明白色表面，导致浅色主题中正文、标题、统计信息和结构化记忆几乎不可读；原生范围选择器的系统下拉菜单还会在深色主题中显示白色背景。

## 证据与复现

- 用户提供的浅色截图显示页面背景为白色，但标题、说明、摘要和条目文本均接近白色。
- 用户提供的深色截图显示范围选择器展开后为白色菜单，菜单项文字仍使用浅色回退色。
- 旧实现位于 `src/client/index.tsx`，使用 `--ds-color-text-primary`、`--ds-color-bg-secondary` 等宿主未提供的变量。

## 影响

记忆内容在两种主题下都存在明显的阅读障碍，范围选择器展开后尤其容易误判或无法辨认项目名称。

## 原因判断

宿主设置模块实际使用 `--dsw-alias-*` 主题变量，例如 `--dsw-alias-label-primary`、`--dsw-alias-bg-layer-2` 和 `--dsw-alias-border-l2`。记忆页沿用了不存在的变量命名，并依赖原生 `<select>` 的系统菜单样式。

## 解决方案

- 将记忆页文本、边框、表面、强调色、警告色和危险色统一映射到宿主 `--dsw-alias-*` 变量，并保留适合浅色主题的回退值。
- 范围选择器使用主题化的背景、文字和边框，并设置 `colorScheme: 'light dark'`；选项同步提供主题颜色，避免继承固定的浅色回退。
- 保持现有原生选择器的键盘和无障碍行为，避免为客户端编译配置引入额外 DOM 运行时依赖。
