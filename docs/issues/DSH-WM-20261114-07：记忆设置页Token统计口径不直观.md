# DSH-WM-20261114-07：记忆设置页 Token 统计口径不直观

## 问题信息

- 发现日期：2026-11-14
- 发现方式：用户审阅记忆设置页的 token 与失败调用统计
- 相关模块或代码：`src/core.ts`、`src/client/index.tsx`、`test/core.spec.ts`、`test/client-theme.spec.ts`
- 状态：已解决
- 验证情况：52 项自动化测试、类型检查、生产构建、peer 检查、打包预检及 `git diff --check` 通过；当前 3080 DSH 已加载本地构建，API 与真实设置页验证通过

## 问题描述

设置页原先同时显示整理调用数、失败调用数、累计总 token 及输入/输出明细，但没有“今日用量”。用户难以感知当天整理成本，而普通用户无法根据累计失败次数采取有效操作。

全局记忆还可能由任意工作区的同一次整理请求顺带产生。模型调用消耗只能准确归属到发起整理的工作区，不能可靠拆分出其中生成全局记忆所占的 token；在全局记忆页面显示 token 会造成归属误解。

## 影响

- 用户不能直接判断当天记忆整理消耗。
- 输入/输出、调用数和失败数增加设置页噪声，但没有提供相应诊断详情或操作价值。
- 全局记忆 token 数字容易被误解为全局条目自身的独立整理成本。

## 解决方案

1. 每个工作区持久化 `todayDate` 与 `todayTokens`，按 DSH 服务所在机器的本地自然日滚动；跨日读取时今日用量立即显示为 0，累计用量不变。
2. 旧状态升级后保留累计用量，但不把无法确定日期的历史 token 计入今日。
3. 工作区设置页使用两行显示“今日整理”和“累计整理”；每行包含总 Token、缓存命中 Token 和缓存命中率，不再显示整理调用数、失败调用数和历史整理次数。
   数值小于 1,000 时显示整数，达到 1,000 后使用 K，达到 1,000,000 后使用 M，最多保留两位小数；悬停显示精确 Token 数。
4. 缓存命中率使用 `cacheReadTokens / (inputTokens + cacheReadTokens + cacheWriteTokens)`，只衡量模型输入上下文的缓存复用比例，输出 Token 不进入分母。
5. 全局记忆和回收区不显示 token；消耗始终归属到发起模型整理的工作区。
6. 底层继续保留调用、失败和输入/输出统计，供日志、API 和后续诊断使用。
7. 用户仍通过待整理数量和后台状态了解处理进度；只有暂停时展示最近错误与“立即重试”。

## 处理记录

- 2026-11-14：确认 token 归属应以发起整理的工作区为准，全局条目不具备可审计的独立 token 分摊依据。
- 2026-11-14：开始实现本地自然日用量桶与设置页信息精简。
- 2026-11-14：新增 `todayDate` 和 `todayTokens` 持久化字段；读取跨日状态时今日用量归零，下一次调用从新自然日重新累计，历史累计用量保持不变。
- 2026-11-14：工作区页面改为只显示今日与累计总 token；全局记忆、回收区、整理调用数、失败调用数、输入/输出明细和历史整理次数不再出现在普通界面。
- 2026-11-14：底层调用数、失败数、输入/输出、缓存、推理与总 token 统计继续保留，暂停时仍显示最近错误和“立即重试”。
- 2026-11-14：按用户确认增加整数/K/M 自适应单位和精确值悬停提示，例如 `860 Token`、`3.28K Token`、`1.24M Token`。
- 2026-11-14：补充今日输入、缓存读取和缓存写入持久化统计；设置页改为今日/累计两行，并在每行显示缓存命中 Token 与命中率。
- 2026-11-14：缓存命中率只以输入上下文为口径，避免输出量稀释缓存复用比例。
