# DSH-WM-20261027-01：DSH 0.2.1 兼容门禁拒绝记忆插件 0.2.15

## 问题信息

- 发现日期：2026-10-27
- 复现方式：在 DeepSeek Harness 桌面版的插件管理器中安装 `@flowingspring/dsh-workspace-memory@0.2.15`
- 相关模块或代码：根 `package.json`、`src/index.ts`、`src/client/index.tsx`
- 状态：处理中
- 验证情况：兼容迁移和自动化回归已完成；35 个测试、类型检查、peer 检查、生产构建、服务端导入、客户端 bundle 加载和隔离安装烟测通过；尚未发布兼容版本，也未在真实 `web` / `desktop` profile 中完成安装启动验收

## 问题描述

记忆插件最新发布版 `0.2.15` 的 peer dependency 仍限定在 DSH `0.1.1-rc.x` 系列。DeepSeek Harness `0.2.1-rc.2` 的插件兼容门禁因此拒绝安装，桌面 profile 当前没有安装或启用该插件。

## 证据与复现

桌面插件管理器日志：

```text
C:\Users\QUAN\.dsh\profiles\desktop\.plugin-manager\logs\operation-DzHP1M\pnpm.log
```

日志明确报告：

```text
Plugin @flowingspring/dsh-workspace-memory@0.2.15 is incompatible with dsh 0.2.1-rc.2
```

根 `package.json` 对 `dsh-agent`、`dsh-llm`、`dsh-session`、`dsh-tools` 等核心包仍声明 `^0.1.1-rc.x`，而本机共享运行时包均已为 `0.2.1-rc.2`。

客户端清单仍同时声明并注入 `@deepseek-ai/dsh-client-runtime`。本机 DSH `0.2.1-rc.2` 的 `@deepseek-ai` 包目录中已不存在该包；新版设置页仍提供 `settings.section`，但 slot 类型与服务图已迁移到 `dsh-client-ui-slots` 等新版客户端服务。

服务端源码还存在两处可确认的旧 API：

- `src/index.ts` 直接读取 `agent.session.events`，而新版 `Session` 的事件日志已私有化。Memory 需要的是当前模型可见的用户与助手消息，因此应迁移到 `deriveMessages()`；`snapshotEvents()` 虽暂时保留，但已被标记为迁移期旧接口，不适合新增调用。
- `src/index.ts` 调用 `sessionPersistence.inspect()`，而新版 `SessionPersistence` 已移除该接口。当前调用只需要会话 header 中的 `cwd`，应迁移到更轻量的 `stat()`；只有读取完整事件正文的场景才需要 `open/read/close`。

其他关键接口初步仍存在：`agent/pre-step`、`agent/turn-stopping`、`agentDefaultModel.currentSelection()`、`webServer` 以及设置页 `settings.section`。这些事实说明迁移范围预计小于 Voco，但不是只改 peer dependency 即可。

只读导入检查结果：

```text
memory: IMPORT_OK
```

这说明当前发布包的服务端入口没有像 Voco 一样立即触发缺失导出错误，但不等于完整兼容；客户端加载、服务注册、工具执行、记忆整理和持久化尚未在新版核心下完成回归。

## 影响

- 桌面插件管理器拒绝安装记忆插件 `0.2.15`。
- 桌面 profile 当前既没有该依赖，也没有对应 bundle。
- Web profile 仍记录 `0.2.15`，但旧清单存在不能替代新版运行时兼容验证。

## 原因判断

插件发布时面向 DSH `0.1.1-rc.x`，尚未更新到 `0.2.1-rc.x` 的兼容契约。除版本门禁外，客户端运行时包已经拆分，Session 事件读取和持久化读取接口也已经变化。现有服务端入口的运行时导入较少，因此实际迁移规模可能小于 Voco；仍需以新版类型检查和真实功能回归为准，不能只扩大 peer dependency 范围。

## 解决方案

1. 参考 Voco 已验证的版本矩阵，将 Cordis、Schemastery 和 DSH 开发依赖精确升级到 `0.2.1-rc.2`，peer dependency 调整为兼容 `^0.2.1-rc.2`。
2. 移除 `dsh-client-runtime`，按新版实际服务补齐客户端类型声明与 inject 清单。
3. 将会话内容读取迁移到 `deriveMessages()`，排除 Memory 自己注入的检索上下文，避免召回内容被再次蒸馏；将持久化 header 查询迁移到 `stat()`，并用类型检查继续暴露其余 API 断裂。
4. 增加兼容契约测试，防止旧包名、旧 peer 范围或错误客户端注入再次进入发布包。
5. 在命令行 `web` 和桌面 `desktop` profile 中验证安装与启动。
6. 回归记忆写入、检索、会话整理、父子会话归集、重启恢复、设置页和 Browser API。
7. 发布兼容版本后确认新版插件管理器不再要求精确版本豁免。
